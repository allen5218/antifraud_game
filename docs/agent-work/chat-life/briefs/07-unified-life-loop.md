# 統一生活事件流：取消模式選擇與答案提示

## 問題

目前首頁要求玩家先理解「題組訓練、滑卡辨識、防詐天賦、社區守護、真實案件、實驗沙盒」等模式；進入聊天後，又出現行動、查證與判斷入口。這些入口增加選擇阻力，也會把反詐方法變成顯眼提示。

玩家應該感覺自己正在幫身邊的人處理生活事件。題目、道具、人物關係、資產與案件知識只是可使用的資源，不是彼此分離的遊戲模式。

## 核心循環

1. 首頁出現一件正在發生的生活事件，例如新訊息、來電、住處事件或朋友請託。
2. 玩家進入自然對話，自行追問缺少的資訊。
3. 玩家可以只靠對話，也可以主動打開自己的工具包、聯絡人、資產或案件紀錄。
4. 玩家採取做法後，事件回應其實際行為，而不是只判定「詐騙／不是詐騙」。
5. 結果改變金錢、人脈、處置記憶、經驗、住處及後續人物事件。
6. 資產與關係產生新的事件，重新回到首頁生活動態。

`生活事件 → 自行探索 → 使用既有資源 → 承擔後果 → 成長與資產改變 → 新事件`

## 首頁改造

首頁不再顯示模式九宮格。首頁只保留三類內容：

- **現在要處理的事**：最新未讀訊息、暫停中的事件與即將到期的生活事件；第一張卡只有一個「繼續」入口。
- **今天的生活動態**：資產收益、朋友近況、住處或車輛帶來的新事件。
- **最近留下的影響**：上一件事造成的人脈、金錢或信任變化，讓玩家理解行為的長期後果。

底部導覽使用玩家能理解的世界概念：`動態 / 聯絡人 / 住處 / 我的`。不在主要導覽暴露訓練模組名稱。

## 聊天操作

聊天標題列不顯示「行動、查證、處理」三個帶答案色彩的按鈕。

輸入框旁只保留一個中性的 `＋`。打開後顯示玩家已擁有的資源類別：

- 我的物品
- 聯絡人
- 住處與車輛
- 過往紀錄

系統不得替玩家排序「本案最適合」的物品，不顯示推薦、匹配、成功率或發光提示。列表可以顯示物品本身一貫的用途，例如「掃描紙本並保存」，但不能寫「這一案應該使用」。

玩家選擇資源後，系統把行為自然寫進對話，例如「我先把這份紙本掃描留存」，再由故事規則回傳可觀察結果。結案入口放在對話選單中，使用中性的「先停在這裡／我決定這樣處理」，不要求先選詐騙標籤。

## 如何讓玩家主動查看道具

不要用紅點、發光或 NPC 明說道具名稱逼玩家查看。動機來自故事中的資訊缺口：

- 對方只說「我手上有一份紙本」，不說「請使用掃描器」。
- 玩家知道自己的物品具有穩定用途，因此想到打開工具包。
- 物品在不同事件中保持同一個現實能力，不為了劇情臨時變成功能不同的魔法道具。
- 使用後給具體的新資訊或新選擇，不直接宣布真假。
- 結案後才可顯示錯過的可能性，例如「若有留下文件版本，後續較容易比對」，供玩家形成下一次的策略記憶。

玩家購買物品的理由應該是「上次缺少這種能力」，而不是商店預告「下一案會用到」。商店可以放在住處的工作桌或手機購物頁，玩家從事件後的缺口主動前往。

## 既有模式的融合方式

| 現有功能 | 融合後的位置 |
|---|---|
| 題組訓練 | 查看合約、訊息或網站時出現的短判讀步驟 |
| 滑卡辨識 | 手機收件匣或社群動態中的快速整理事件 |
| 防詐天賦 | 根據反覆行為自然形成的能力與稱號，不要求玩家先配點 |
| 社區守護 | 成為會主動傳訊、求助、回報結果的真人關係 |
| 真實案件 | 過往紀錄與事件後解鎖的案件檔案 |
| 實驗沙盒 | 玩家準備回覆、整理說法或預演風險的記事工具 |
| 快速測驗 | 日常事件中的短插曲，不再是獨立刷題入口 |
| 資產系統 | 住處、車輛與設備提供事件場所、能力與生活成本 |

後端可以暫時保留原有 API 和頁面以降低改造風險，但玩家主流程不再看見模式切換。

## 獎勵原則

- 獎勵查證過程、風險控制和守信行為，而不是只獎勵猜中詐騙。
- 同一資源在同一事件只能產生一次有效收益。
- 高倍率來自連續處理與長期關係後果，不由單次按鈕隨機爆發。
- 房屋、車輛與設備必須能產生事件、降低成本、提供行動條件或改變人物關係；只有收藏價格的資產不進主循環。
- 失敗也能留下可使用的經驗或紀錄，但不能用低成本故意失敗刷資源。

## 分階段落地

### 第一階段：取消選單式提示

- 移除聊天標題列的行動、查證、處理按鈕。
- 輸入框增加單一 `＋` 工具包。
- 工具包只列已擁有資源，不依目前故事推薦或排序。
- 資源使用結果回到聊天訊息流。

### 第二階段：首頁變成生活動態

- 以最新事件和「繼續處理」取代 `PlayModeGrid`。
- 將暫停事件、未讀聯絡人和資產事件排進同一時間流。
- 保留既有模式路由作為內部功能，主流程不直接展示。

### 第三階段：把模式變成事件節點

- 合約判讀呼叫題組機制。
- 收件匣整理呼叫滑卡機制。
- 事件後自動寫入案件紀錄和人物記憶。
- 住處、車輛和家具定期產生或改變事件。

### 第四階段：成長與留存校準

- 記錄玩家是否主動打開工具包、使用哪些資源、何時退出及是否回來續辦。
- 以完成一條人物故事、再次主動回訪和跨事件使用資源作為黏著指標。
- 根據真實玩家資料調整成本與成長速度，不先用高倍率掩蓋流程阻力。

## 第一階段驗收

1. 新玩家進入首頁後，不需要理解任何「模式」名稱即可開始一件事。
2. 聊天畫面不顯示本案可採取的建議行動或可查證數量。
3. 玩家可以在不知道標準答案的情況下自由對話。
4. 玩家主動打開工具包後，只看到自己擁有的東西及其固定用途。
5. 選擇物品會在聊天中形成自然行為與可觀察結果，不直接揭曉真偽。
6. 玩家可在事件後理解金錢、人脈、經驗與資產如何改變下一件事。
