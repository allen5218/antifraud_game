## 必須修正

### P1：每日訓練解鎖門檻寫錯

原後端 backend/app/economy/levels.py 的門檻為 [0, 100, 300, 600, 1000, ...]，因此訓練 Lv.5 是 1000 XP；400 XP 僅為 Lv.3。不可為測試修改原等級表或降低每日訓練門檻。

目前 frontend/src/routes/_shell/leaderboard.tsx:75 使用 400 - trainingXp 計算缺口。Codex 已在實際背景瀏覽器重現：正常新帳號為 XP 0／Lv.1，畫面卻顯示「還差 400 訓練 XP」。應改為正確 1000 XP 的差額。

scripts/run-gameplay-eval.mjs 的 daily_unlocked_round、四輪後每日訓練探針、相關註解、斷言與 dailyUnlockedAtRound:4 皆使用同一個錯誤假設。請以真實 economy.level >= 5 判斷解鎖，在正常獎勵下繼續作答直到解鎖。全對每輪原訓練經驗 100，需十輪才達 1000；不得加經驗。驗證 999 以下鎖定、1000 解鎖的規則時遵守原環境及測試方式。

### P2：回本分析是硬編文案，未由測試資料計算

runPartCTradeoffAndSeasonQualification 雖收了 partBResults，回傳的 roiAnalysis 仍為固定文字，例如「全對約 8～9 輪」與「全對約 38 輪」。請從逐輪真實基礎收入、開局核心／寵物／工具快照，分別計算有無該次強化的向下取整獎勵差額，再累加到成本。輸出每輪差額與假設，讓報告可回算。

若十輪尚未回本，報告寫「十輪尚未回本」並另列固定狀態推算，不將超過觀測範圍的輪數當作已實測。與策略順序及核心成長有關的回本，不能用一個手填區間替代。

### P2：有限槽只驗證禁止裝備，未完成真正取捨

runLiveSlotSwapAndDailyQualificationProbe 檢查第三工具在 2/2 槽下不可裝備後，就直接進每日訓練，沒有實際卸下與交換。

請接著卸下一件、裝上第三件、核對生效家族與槽數、重載保存，並開下一局核對新快照及收益。舊局仍維持原快照。完成後才能回報 slotCapacityTradeoffVerified:true。

### P2：失敗時未保存已完成的證據

目前 main 僅在 Part A／B／C 全部結束後才寫 JSON，失敗則只 console.error 和 exit(1)。後段一個問題會讓已跑三十輪的結果無完整產物可查。

請每個階段／輪次保存經遮蔽的檢查點；失敗輸出包含階段、斷言、已完成結果與日誌的失敗報告，仍保持非零 exit。不要將失敗檢查點當成功報告。
